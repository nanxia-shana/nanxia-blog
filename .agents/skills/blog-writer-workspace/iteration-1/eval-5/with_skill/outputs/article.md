# 学习 Rust 一个月，我终于理解了所有权

## 1. 开篇：被编译器按在地上摩擦

说出来你可能不信，我学习 Rust 的前两周，基本上每天都在跟编译器吵架。

```
error[E0382]: use of moved value: `s`
 --> src/main.rs:4:17
  |
2 |     let s = String::from("hello");
  |         - move occurs because `s` has type `String`, which does not implement the `Copy` trait
3 |     let s2 = s;
  |              - value moved here
4 |     println!("{}", s);
  |                 ^ value used here after move
```

这个报错，我前前后后看了不下一百遍。

作为一个写了五六年 JavaScript 和 Python 的人，我从来没想过把一个变量赋值给另一个变量，居然会报错。而且不是运行时报错，是编译阶段就给你卡死了。

当时的内心 OS：
- 这不就是最基本的赋值操作吗？
- 为什么其他语言都好好的，就 Rust 事多？
- 这语言设计得是不是反人类？

我甚至一度想要放弃。

::: tip 真实经历
头三天我写的每一行代码几乎都在报错，复制一个字符串我都要查半天文档。朋友问我 Rust 学得怎么样了，我说："我现在跟 borrow checker 不共戴天。"
:::

## 2. 第一次开窍：栈和堆的区别

事情的转机发生在我重新开始复习计算机基础知识的时候。

为了搞懂所有权，我翻出了当年的《深入理解计算机系统》，重新看了关于栈和堆的章节。然后突然之间，好像有什么东西通了。

原来，Rust 的所有权机制不是凭空造出来的，它本质上是在编译期就帮你管理堆内存的生命周期。

我们来回忆一下：
- **栈上的数据**：大小固定，自动分配，自动释放，拷贝成本低
- **堆上的数据**：大小动态，手动分配，手动释放，访问需要通过指针

在 C/C++ 里，堆内存需要你自己 malloc 和 free。忘了 free 就内存泄漏，提前 free 了就悬垂指针，free 两次就 double free。

在 Go/Java 里，有垃圾回收（GC）帮你管，但代价是运行时的 Stop The World 和额外的性能开销。

而 Rust 选择了第三条路：**在编译期就确定每一块堆内存什么时候该释放，不需要 GC，也不需要手动管理**。

所有权就是干这个的。

```rust
fn main() {
    let s = String::from("hello"); // s 进入作用域，堆内存分配
    takes_ownership(s);            // s 的值被移动进函数
                                   // s 在这里不再有效
    // println!("{}", s);          // 这里会报错！
} // s 已经被移走了，什么都不会发生

fn takes_ownership(some_string: String) {
    println!("{}", some_string);
} // some_string 离开作用域，drop 自动调用，堆内存释放
```

看懂这段代码的时候，我鸡皮疙瘩都起来了。

原来不是 Rust 不让你用，是它在帮你擦屁股。当你把 `s` 传给函数的时候，Rust 知道这个变量的所有权已经转移了，所以在那之后你就不能再用它了——因为内存可能已经被释放了。

在其他语言里，你当然可以继续用，但那要么是造成了一次隐式的深拷贝，要么就是给 GC 增加了负担，要么——就是一个潜在的 bug。

## 3. 借用和生命周期：不是不让你用，是让你用得安全

理解了所有权之后，借用（Borrowing）就顺理成章了。

Rust 不是吝啬鬼，不是说你把变量给了别人就再也用不了了。你可以把变量"借"出去用，但是要遵守规则。

借用的核心规则其实只有两条：
1. 同一时间，你要么只能有一个可变借用，要么可以有多个不可变借用
2. 借用必须总是有效的

听起来很简单对吧？但就是这两条规则，在编译期就消灭了数据竞争和悬垂指针。

我之前写 C++ 的时候，踩过一个印象特别深的坑：

```cpp
std::vector<int> vec = {1, 2, 3};
int& ref = vec[0];
vec.push_back(4);  // 可能导致 vec 重新分配内存
std::cout << ref;  // 悬垂引用！UB！
```

这段代码在 C++ 里是可以编译通过的，甚至大部分时候运行起来好像也没问题。但它是未定义行为，指不定什么时候就炸了。

而在 Rust 里，同样的逻辑：

```rust
let mut vec = vec![1, 2, 3];
let ref_val = &vec[0];
vec.push(4);  // 编译报错！
println!("{}", ref_val);
```

直接就给你报 `cannot borrow `vec` as mutable because it is also borrowed as immutable`。

一开始你会觉得烦人，但是仔细想想——Rust 在保护你啊！它知道 `push` 可能会导致 vector 重新分配内存，那之前的引用就失效了。所以它不让你这么干。

::: danger 踩坑提醒
我当时为了"绕过"编译器，写过不少既不优雅也不高效的代码。比如到处 `clone()`，或者用 `Rc<RefCell<T>>` 大杀器。后来才明白：当你觉得借用检查器在跟你作对的时候，往往是你的代码设计本身就有问题。
:::

## 4. 真正的领悟：所有权是一种思维方式

大概学了三周左右的时候，我发现我写 Rust 的思路变了。

以前写代码，我会先想"这里需要一个对象，把它传过去就好了"。

现在写 Rust，我会先想：
- 这个数据谁拥有它？
- 这里是需要所有权，还是只需要借用？
- 如果是借用，要借多久？
- 这个变量的生命周期和那个变量的生命周期是什么关系？

有意思的是，这种思维方式开始影响我写其他语言的代码了。

前几天写 TypeScript，我写着写着突然停下来问自己："这个对象在这里会不会被意外修改？我是不是应该传一个只读的副本？"

然后我意识到，在 TS 里当然没有编译器强制你这么做，但是这个意识已经刻进脑子里了。

这才是 Rust 给我最大的收获——它不是让你学会一门新语言，而是让你学会一种新的思考方式。你开始真正关心数据在内存里的状态，关心每一块内存的来龙去脉。

你写的代码可能变慢了（开发速度），但是你对你写的每一行代码都更有信心了。

## 5. 写在最后

现在有人问我 Rust 难不难学，我会说：难，但是值得。

所有权、借用、生命周期，这些概念确实不是一两天就能搞懂的。前两周你可能每天都在怀疑人生，都在想为什么要给自己找这个罪受。

但是等你真正跨过去那个坎之后，你会看到不一样的风景。你会明白为什么那么多人对 Rust 推崇备至，你会开始怀念其他语言里也有一个 borrow checker 帮你擦屁股。

而且说实话，当你终于把一段写了两天的代码编译通过，然后它一次就运行成功的时候——那种成就感，真的很爽。

我现在还不敢说我精通 Rust，甚至不敢说我完全掌握了所有权。还有很多复杂的场景我处理不好，还有很多 lifetimes 的标注让我头疼。

但是没关系，慢慢来。

至少现在，我看到 `error[E0382]` 的时候，不会再想摔键盘了。
